# White-glove audit — deliverables and standardized process

**4 August 2026 · backend and frontend · Sean Gilmore**

**The question:** which standardized processes and deliverables does the
codebase already imply, and which of them should become skills (`/nest-credit-memo`
and its siblings)?

**Method:** every claim below was read from the code this pass, not recalled.
File and line numbers are given so each is checkable. Confidence: `verified`
unless marked otherwise.

---

## The headline

**The platform has rigor where it produces nothing, and produces things where
it has no rigor.**

The engines carrying real analysis — `preflight`, `success_predictor`,
`stairway`, `document_package`, `gate_fee_engine` — have **no deliverable
generator between them**. They return structured data that a human has to
turn into a document by hand, which is why this session hand-rolled the same
script six times.

Meanwhile the modules that *do* emit deliverables are either ungrounded prose
generators or thin dictionary shufflers that call no analysis at all.

That inversion is the finding. Everything below is detail.

---

## 1 · `credit_memo_agent.py` — the most dangerous file in the repository

45 lines. `backend/agents/credit_memo_agent.py`. It should not be wrapped in a
skill; it should be replaced.

### 1.1 It is an unguarded prose generator

`generate_memo()` builds an eight-field prompt string and returns raw model
output (line 33). No structure, no validation, no schema. Whatever comes back
is the credit memo.

### 1.2 It is instructed to write things it has not been given

The system prompt requires:

> `2. BORROWER PROFILE (sponsor, management, track record, sector)`
> `5. RISK FACTORS (top 3-5 risks with mitigants)`

The prompt supplies a sponsor **name** and nothing else. There is no track
record in the input, no management detail, no risk data. The model will
therefore **invent a track record, invent management, and invent three to five
risks with mitigants** — and present them in a document formatted to look like
a credit committee paper.

This is the same failure that put six imaginary institutional buyers into
`routes/hawkeye.py`, except the output here is a document a client reads.

### 1.3 Missing data silently becomes a catastrophic number

```python
DSCR: {deal.get('dscr', 0):.2f}x | Leverage: {deal.get('leverage', 0):.1f}x
```

A deal with no DSCR renders as **`DSCR: 0.00x`**. The model is not told this
means "unknown" — it is told coverage is zero, and instructed to treat numbers
as authority. A missing field produces a memo confidently analysing a deal at
zero coverage.

### 1.4 It is told to be certain

> `Tone: Direct, analytical, no hedging. Lead with conclusion. Numbers are authority.`

Instructing maximum confidence about figures the model may have invented is the
exact inverse of the truth-shield discipline. `verified` — line 18.

### 1.5 It does not know what the platform knows

It calls **no engine**. Not preflight, not the predictor, not the document
package. On Horn Lake the engines return `RESTRUCTURE`, four structural traps,
and a 29% probability of close. A credit memo generated by this agent would
contain none of that, because it has never been told.

### 1.6 Its thresholds contradict preflight

| Threshold | `UNIVERSAL_CREDIT_POLICY` | `preflight.py` | Conflict |
|---|---|---|---|
| Max leverage | `0.80` (line 81) | `MAX_DEBT_TO_COST = 0.75` (line 58) | **Yes** |
| DSCR floor | `1.20` (line 79) | `1.10` absolute / `1.20` enhancement | Overlapping, different meanings |

A deal at 78% LTC **passes the credit policy and fires `OVERLEVERED` in
preflight.** Two modules, two answers, no reconciliation. `verified`

## 6 · Recommendation

**Do these in order. The order matters — two of them are prerequisites.**

**1 · Delete the fabricated buyer universe.** `routes/hawkeye.py:26`. Live
misrepresentation. One line of work, no dependencies.

**2 · Reconcile the fee sources to one.** `gate_fee_engine.py` should be the
single source; everything else reads from it. Until this is done, no fee
deliverable can be automated honestly.

**3 · Reconcile leverage and DSCR** between `UNIVERSAL_CREDIT_POLICY` and
`preflight.py`. Pick one, delete the other, or state explicitly why a credit
screen and a structural screen use different numbers.

**4 · Build `/nest-credit-memo` as a replacement, not a wrapper.** The
specification:

- Takes a deal, **runs the engines**, and builds the memo from their output
- Every number traceable to an engine call; nothing from the model's own head
- Missing input renders as **"not provided"**, never as `0.00x`
- Thresholds read from `preflight.py`, never restated in a prompt
- Risk factors come from `preflight` traps, not invention
- Recommendation comes from `deal_preflight_flow`, not prose
- Prose is confined to *narrating* structured findings, never sourcing them
- The memo states what could not be assessed

**5 · Build `/nest-client-brief`** on `stairway_full()` — preflight, pathway,
alternatives. This is the deliverable NEST sells and it has no generator.

**6 · Then wire a frontend**, starting with `ClientDepositPlatform.tsx` against
`/api/gate-fees/client-view`.
